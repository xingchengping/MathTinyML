MathTinyML (The content here is the same as MathTinyML.md.)

Running neural nets on potato-tier MCUs using pure math. No bloated frameworks, no <cmath>, no malloc().

I got sick of TensorFlow Lite for Microcontrollers or PyTorch eating up all my SRAM and clock cycles on embedded devices. FPU operations like exp() are way too slow for extreme-edge devices. So I threw out the standard approach and built an inference engine driven entirely by polynomial approximations and matrix factorization.

I'm 14, so I don't have time to write a massive codebase. This is a single-header library. Just drop it in and compile.

 Quick Start

What this is

You have a trained neural network (PyTorch, TensorFlow, or TFLite). You want to run it on an ESP32 or similar MCU without TensorFlow Lite Micro eating all your RAM. This project does that — single header, pure math.

Step 1: Export your model weights

Run the GUI and pick your model file:

```bash
python export_weights.py
```

A window opens. Click **Browse...** to select your `.pt`, `.h5`, or `.tflite` file. Click **Detect Layers** to see all the Dense/Linear layers inside. Pick a rank (smaller = more compression), then click **EXPORT WEIGHTS**.

This creates a file named `model_weights.h` containing all your model's layers, each compressed with SVD.

Step 2: Drop it into your Arduino project

Copy these two files into your Arduino/PlatformIO project folder:

- `MathTinyML.hpp`  (the inference engine)
- `model_weights.h` (your model's weights, from Step 1)

Step 3: Write a few lines of code

```cpp
#include "MathTinyML.hpp"
#include "model_weights.h"

uint8_t pool[16 * 1024];  // adjust size if your model is larger
MathTinyML::ArenaAllocator arena(pool, sizeof(pool));

void loop() {
    float input[...]  = { /* your sensor data, same format as training */ };
    float output[...]; // size = your model's output dimension

    MathTinyML::sequential_forward(&arena, MTML_LAYERS, MTML_NUM_LAYERS, input, output);

    // output[0], output[1], ... are your predictions. Done.
}
```

That's it. No TensorFlow. No `malloc()`. No `<cmath>`. Just matrices and polynomials.

What you can throw away

If you were using TensorFlow Lite Micro before, you can delete ALL of this:

```cpp
// ✗ Delete these — you don't need them anymore
#include "model_data.h"
#include <tensorflow/lite/micro/micro_interpreter.h>
#include <tensorflow/lite/micro/all_ops_resolver.h>

constexpr int kArena = 128 * 1024;     // 128KB → now only 16KB
uint8_t arena[kArena];
tflite::MicroInterpreter* interpreter;
```

How it works (The Math)

1. Killing exp() with Chebyshev Approximation

Modern activations (GELU, Softmax) rely on $e^x$. Calling standard math libraries on an MCU for every parameter is a death sentence for performance. Taylor expansion is garbage the moment you move away from $x=0$.

Instead, I mapped the activation domain to $[-3, 3]$ and used first-kind Chebyshev Polynomials $T_n(x)$ to get a Minimax approximation.

$$P_k(x) = \sum_{i=0}^k c_i x^i \approx \text{GELU}(x)$$

Why this matters: The Chebyshev truncation error has a $2^n$ damping factor in the denominator.


$$E_n(x) \le \frac{1}{2^n (n+1)!} \max_{-1 \le \xi \le 1} |f^{(n+1)}(\xi)|$$

It guarantees a strictly bounded worst-case error. Evaluated using Horner's method, computing GELU now takes exactly 3 multiplications and 3 additions per value. Constant time $O(1)$. No branching. Pipeline stays happy.

2. Shattering the SRAM wall with SVD

A standard $768 \times 768$ weight matrix is ~2.3MB. It simply doesn't fit on an MCU.
Since neural nets are intrinsically low-rank, I apply Singular Value Decomposition (SVD) and aggressively truncate the singular values, keeping only the top $r$.

$$W \approx \hat{W} = U_r \Sigma_r V_r^T = A_{m \times r} B_{r \times n}$$

Forward pass goes from $O(m \times n)$ MACs to $O(r(m+n))$. For $r=32$, that's a 91.6% reduction in both memory and compute. By the Eckart-Young-Mirsky Theorem, the perturbation error is strictly bounded by the largest discarded singular value:


$$||y - \hat{y}||_2 \le \sigma_{r+1} ||x||_2$$

3. Zero-Allocation Memory

malloc() leads to fragmentation, which leads to your MCU crashing 3 days later.
This engine uses a static arena allocator. You give it a chunk of SRAM at boot, and all tensors are allocated via pointer bumping with strict 4-byte alignment. Garbage collection costs zero CPU cycles (just reset the offset to 0 after the forward pass).

Real-world benchmark — 7-layer Dense network on ESP32

| | TFLite Micro | MathTinyML (r=9) |
|---|---|---|
| Arena needed | 128 KB | ~16 KB |
| Framework overhead | 100+ KB | 0 (single header) |
| Every layer SVD-compressed | No | Yes |
| Weight storage | 201 KB | ~40 KB |

The same model that required the full TensorFlow Lite Micro stack now runs in a single `.hpp` + one generated header.


Requirements

- Python 3.8+ with `numpy`. For loading models: `torch` (PyTorch), `tensorflow` (Keras), or `tflite` (TFLite).
- Any C++17 compiler for the MCU side. Tested on ESP32 (Arduino) and ARM Cortex-M4.
